# 评测与简历证据口径

所有运行创建带时间戳目录，保留 CSV、metadata.json 和 report.md。元数据含上游 commit、模型名、temperature、数据集 SHA256。数据在 devflow/benchmarks/data 下随包分发；generate_data.py 是可审阅的构造来源，不生成目标分数。

## 工具

6×40 条由 10 类场景与 4 种文件/模块变体组成，含中文与带空格路径。每条记录 expected_tool、required_fields、fixture、arguments 与 expected_outcome。当前标签为工程模板人工规则，尚未做多标注者一致性复核；不要宣传为行业标准测试集。

离线评估 expected_outcome 是否与实际状态/错误码一致。正常成功和正确拒绝均可通过该检查，但工具选择准确率不适用于离线模式。
Live 向模型发送固定系统提示、全部六工具 Schema 和单条请求；单次恰好一个工具且名称吻合才算选择正确。无调用、多调用、网络错误均进入分母。
Schema 通过率对 Pydantic 模型校验；全量包含刻意非法参数，另报合法输入子集。调用参数正确性、执行是否 SUCCESS、选择正确是三件不同的事。

## Context

12 个小型计算模块修复任务，每组固定 20 轮。初始文件分别复制到 A/B，A 禁用压缩/Observation 截断并扩大默认 Read，B 使用产品策略。同一模型、temperature、工具环境。
Live 累计输入从生产 Trace 的 llm_request.input_tokens 聚合。确定性摘要不产生 summary_input_tokens，值为 0；将来换模型摘要必须加上其用量。缺失 usage 的实验不生成 Token 节省率。
状态为最终回答对 5 个预埋点的字面命中（标记、函数名、依赖约束、修改文件、测试文件），共 60 点。这不能证明复杂语义完全正确，公开报告需保留该限制。
重复 Read：同任务相同路径，读取行区间和任一旧区间重叠，计为 1 次重复；缺省 end_line 以产品默认 200 行推算。文件改变后的合理重读仍计入，分析时应查看 Trace。
完成率使用独立验收脚本验证 4 个输入，不相信 Agent 的“测试通过”自述。

离线回放只验证相同消息轨迹下的截断和压缩，没有模型任务推理。回放重复 Read 固定不变，其下降率应是 0，而不是目标 24.1%。离线大日志下的 Token 节省不可用作简历真实模型数据。

## 恢复

模型请求异常 10 次；Tool 已执行但结果未持久化时强制退出 10 次（包含文件和命令）；TODO append 后退出 10 次，其中 5 次额外写入半行。
真实子进程通过 os._exit 退出，不执行 finally。父进程恢复生产 SessionManager、关闭未完成 tool-call 协议对，继续调用原生 Runtime，并再次重启检查日志仍可追加。
成功是“最近一致历史恢复并能够继续”，不是原任务自动完成，也不是副作用 exactly-once。结果未知必须单列；不要为了匹配简历 96.7% 人为注入一个伪失败。
本机的断电、磁盘硬件写缓存故障、网络文件系统和恶意并发外部写入没有模拟。

## 简历更新原则

97.9%、98.8%、38.6%、98.3%、24.1%、96.7% 都是原需求的模拟目标，不写入实现或报告常量。
未跑 live 前可写“实现六类工具、240 条回归数据、12×20 轮评测框架、30 次进程级故障验证”。
完成 live 后以该运行报告替换指标，同时保留模型、运行时间、数据版本和失败案例。
